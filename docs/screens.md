# 画面要件

本ドキュメントは、既存の requirements.md を前提として、SNSアプリの画面要件を整理する。

> 未確定事項は、原則として「未決定」または「後工程で検討」と明記する。
> 仕様を推測して追記しない。
> 本書にはMVP対象と将来仕様の両方を含む。MVPへの採否は [mvp.md](./mvp.md) を参照し、設計記載を実装済みとみなさない。

---

## 認証系

### ログイン

- メールアドレス
- パスワード
- ログイン
- 新規アカウント作成への遷移
- パスワード再設定への遷移（画面・ルートは将来仕様）
- ログイン成功後、安全な `callbackUrl` があれば元の画面へ遷移し、ない場合・不正な場合はCanvasへ遷移
- 有効なログイン状態が残っている場合はログイン画面を経由せずCanvasを表示

補足:
- 認証方式の詳細は後工程で検討
- セッション管理の実装方式は後工程で検討

### 新規アカウント作成

- メールアドレス
- パスワード
- パスワード確認
- 表示名
- 生年月日（任意）
- 登録成功時に一意かつ変更不可の固定ユーザーIDを自動発行
- 登録完了後はログイン画面へ遷移
- メール認証についてはMVP検討時に判断

補足:
- 文字数制限や入力バリデーションは後工程で検討
- 固定ユーザーIDの採番ルールは後工程で検討

### パスワード再設定

将来仕様（画面・ルートは設計に維持するが、画面・実処理ともMVP対象外）。

- メールアドレス入力
- 再設定処理
- 再設定完了後はログイン画面へ遷移

補足:
- 再設定用トークンやメール送信の仕組みは後工程で検討

# ユーザー側

## Canvas（ホーム・タイムライン）

目的:
- ログイン後のメイン画面
- 投稿を閲覧し、各SNSアクションを行う

機能:
- 投稿一覧表示
- 投稿者情報
- 投稿日時
- いいね / いいね解除
- リプライ
- リポスト / リポスト解除
- 投稿詳細への遷移
- 投稿者プロフィールへの遷移
- 投稿作成Modalを開く
- 自分の投稿削除
- ページネーションまたは無限スクロール
  - 方式は後工程で検討

削除権限:
- 自分の投稿：削除可能
- 他ユーザーの投稿：削除不可
- 管理者：管理機能から削除可能

補足:
- いいね / リポストは同一画面内で完結し、画面遷移は行わない
- リプライを選択した場合は投稿詳細へ遷移し、投稿詳細内でリプライを行う

## 投稿詳細

- 元投稿表示
- 投稿者情報
- 投稿日時
- 本文
- いいね / 解除
- リポスト / 解除
- リプライ入力
- リプライ投稿
- リプライ一覧
- 投稿者プロフィールへの遷移
- リプライ投稿者プロフィールへの遷移
- 自分の投稿 / リプライ削除

補足:
- リプライ専用画面は作成せず、この画面へ統合する
- いいねやリポストの実行は同一画面内で完結するため、専用遷移として扱わない

## My Page（マイページ）

- ヘッダー画像
- アイコン
- 表示名
- 固定ユーザーID
- プロフィール文
- 生年月日
- フォロー数
- フォロワー数
- プロフィール編集への遷移
- Settingsへの遷移
- 投稿作成Modal
- Activity Tabs

Activity Tabs:
- 投稿
- リプライ
- いいね
- リポスト

補足:
- Activity Tabsは独立画面ではなくMy Page内のタブ切り替えとする
- 各タブの投稿選択時は投稿詳細へ遷移する

## 他ユーザープロフィール

My Pageとプロフィール表示用コンポーネントを可能な範囲で共通化する。

- ヘッダー画像
- アイコン
- 表示名
- 固定ユーザーID
- プロフィール文
- 公開設定に応じた生年月日
- フォロー数
- フォロワー数
- フォロー
- フォロー解除
- Activity Tabs
  - 投稿
  - リプライ
  - いいね
  - リポスト

補足:
- 他ユーザーのフォロー数 / フォロワー数は表示のみとし、フォロー / フォロワー一覧への遷移は行わない
- 表示項目の公開設定における判定は後工程で検討

## プロフィール編集

プロフィールのテキスト情報編集はMVP対象。プロフィール画像・ヘッダー画像の変更処理は将来仕様として維持し、MVP対象外とする。

- ヘッダー画像変更
- ヘッダー画像プレビュー
- ヘッダー画像削除
- アイコン変更
- アイコンプレビュー
- アイコン削除
- 表示名編集
- プロフィール文編集
- 生年月日編集
- 生年月日の公開設定
  - 全公開
  - 月日のみ公開
  - 非公開
- 保存
- キャンセル
- バリデーション
- 二重送信防止

補足:
- 固定ユーザーIDは変更不可
- 保存成功後はMy Pageへ戻る
- 未保存の変更が存在する状態で離脱する場合は、変更破棄確認Modalを表示する
- バリデーションの具体的な条件は後工程で検討

## フォロー / フォロワー一覧

1画面内でタブ切り替えを行う。

Tabs:
- フォロー
- フォロワー

My Pageのフォロー数を選択した場合:
- フォロータブを初期表示

My Pageのフォロワー数を選択した場合:
- フォロワータブを初期表示

機能:
- ユーザー一覧
- ユーザープロフィールへの遷移
- フォロー一覧からフォロー解除
- フォロワー一覧で未フォローの場合はフォロー可能

補足:
- フォロー / フォロワー一覧の表示件数制限や並び順は後工程で検討

## Exploration（検索）

ユーザー検索・投稿検索の基本機能はMVP対象。検索の高度化（人気順など）は将来仕様であり、MVP対象外とする。

- 検索フォーム
- ユーザー / 投稿タブ

ユーザー検索:
- 固定ユーザーID検索
- 表示名検索
- ユーザープロフィールへの遷移

投稿検索:
- 投稿本文検索
- 投稿詳細への遷移
- 新しい順
- 人気順（将来仕様・MVP対象外）

検索結果:
- ページネーション等
  - 詳細方式は後工程で検討

補足:
- 人気順の算出ロジックは後工程で検討
- 検索対象の件数上限は後工程で検討

## Inbox（通知）

通知一覧・既読管理・未読件数はMVP対象だが、実装優先順位は後工程とする。リアルタイム通知はMVP対象外。

通知を新しい順で一覧表示する。

通知種別:
- いいね
- リプライ
- リポスト
- フォロー

機能:
- 通知したユーザー情報
- 通知日時
- 既読 / 未読
- 通知種別の視覚的表示
- 通知選択時に既読化

遷移:
- いいね → 投稿詳細
- リプライ → 投稿詳細
- リポスト → 投稿詳細
- フォロー → 他ユーザープロフィール

補足:
- 未読件数の管理とフッターへのバッジ表示はMVP対象。バッジの具体的な表示方法は後工程で検討
- 通知の削除機能は未決定

## Settings

独立画面として作成する。

- アカウント関連
- セキュリティ関連
- パスワード変更
- ログアウト
- アカウント削除
- 固定ユーザーID確認

ログアウトと設定画面の最低限の実装はMVP対象。パスワード変更・アカウント削除の実処理は将来仕様として維持し、MVP対象外とする。

パスワード変更:
- Modal

ログアウト:
- Confirm Modal
- 完了後Loginへ

アカウント削除:
- Confirm Modal
- 完了後Loginへ

補足:
- アカウント削除の実際のデータ削除方式は後工程で検討

# 共通UI

## Header

- App Symbolを左端に配置
- App Symbolはアプリのシンボルとして表示するだけで、クリック・画面遷移機能を持たない
- My Page Iconを右端に配置
- My Page Icon選択時にMy Pageへ遷移

補足:
- Headerのレイアウトやアイコンのデザインは後工程で検討

## Footer

通常のユーザー画面で固定表示する。

- Canvas（ホーム）
- Exploration（検索）
- Inbox（通知）

補足:
- FooterはServer Componentとして実装し、`usePathname`による現在ページのアクティブ表示（色変更）は採用しない（旧方針：現在表示中の項目を視覚的に選択状態にする）
- Inbox（通知）には未読Badgeを表示可能とする
- ProfileEdit / SettingsではFooterを表示しない
- その他の詳細なFooter表示条件は後工程で検討

## Piece Create Modal（投稿作成モーダル）

本文投稿はMVP対象。画像添付は将来仕様として維持し、MVP対象外とする。

独立画面ではなく共通Modalとする。

- 本文入力
- 文字数表示 / 文字数制限
- 画像添付
- 投稿
- キャンセル
- バリデーションエラー
- Loading
- 二重送信防止

補足:
- 画像添付はMVP対象外とし、画面仕様を将来仕様として維持する
- 投稿成功後はModalを閉じ、元画面へ反映する

# 管理者側

ユーザー側とは別のAdmin Layoutを使用する。管理者画面・管理機能は将来仕様として設計に維持し、MVP対象外とする。以下の記載は実装完了を示さない。

## Admin Login

- 管理者ログイン
- 認証成功 → Admin Dashboard
- 認証失敗 → Admin Login
- 一般ユーザーはAdmin画面へアクセス不可

補足:
- フロントエンドの表示制御だけでなく、バックエンド側でも管理者権限を確認する
- 認証方式は後工程で検討

## Admin Dashboard

- 総ユーザー数
- 総投稿数
- 本日の新規ユーザー数
- 本日の投稿数
- センシティブ候補投稿数
- ユーザー登録数推移グラフ
- 投稿数推移グラフ
- 最近登録されたユーザー
- 最近の投稿

補足:
- 最近登録されたユーザー：Admin User Detailへ遷移
- 最近の投稿：Admin Post Detailへ遷移
- グラフの期間切り替えは理想形として保持し、MVP範囲は後で判断する

## User Management

一覧:
- 表示名
- 固定ユーザーID
- 登録日
- アカウント状態
- 固定ユーザーID検索
- 表示名検索
- ステータス絞り込み
- 並び替え
- ページネーション

ユーザー選択時:
- Admin User Detailへ遷移

## Admin User Detail

- DB内部ID
- 固定ユーザーID
- 表示名
- メールアドレス
- 登録日時
- アカウント状態
- 投稿数
- リプライ数
- いいね数
- フォロー数
- フォロワー数
- 投稿履歴
- 利用停止
- 利用停止解除
- アカウント削除

補足:
- 投稿履歴選択：Admin Post Detailへ遷移
- 利用停止 / 解除 / 削除：Confirm Modalを表示
- 必要に応じて理由を記録

## Post Management

- 投稿一覧
- 本文検索
- 固定ユーザーIDによる絞り込み
- 投稿日時による並び替え
- ページネーション
- 投稿詳細への遷移

## Admin Post Detail

一般ユーザー用投稿詳細とは管理目的を分ける。

- 投稿内容
- 投稿者
- 投稿日時
- 管理状態
- 管理者による削除
- 削除理由

補足:
- 削除時はConfirm Modalを表示する
- 削除の物理削除 / 論理削除の種別は後工程で検討

## Sensitive Management

センシティブ候補として選定された投稿を管理する。

- 確認待ち投稿一覧
- Sensitive Detailへの遷移

## Sensitive Detail

- 対象投稿確認
- 問題なし
- 非表示
- 削除

補足:
- センシティブ候補の選定方法は現時点では決定しない
- 候補として以下が挙げられるが、実装時に決定する
  - ユーザーからの通報数
  - 特定ワードによる判定
  - 複数条件の組み合わせ
  - その他

## Audit Log

管理者による操作履歴を閲覧する。

- 日時
- 操作した管理者
- 操作種別
- 対象
- 操作内容

補足:
- 基本的に閲覧専用とする
- 操作履歴の保存期間は後工程で検討

# IDの扱い

以下を明確に区別する。

DB内部ID:
- DB内部で使用
- リレーション等に使用
- 一般ユーザーには基本的に表示しない

固定ユーザーID:
- アカウント作成時に自動生成
- 一意
- 変更不可
- ユーザーを外部から識別するために使用

表示名:
- ユーザーが変更可能
- 重複可能
