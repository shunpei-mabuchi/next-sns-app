# 要件定義

## 1.目的

本プロジェクトは、Next.jsをフロントエンド、NestJSをバックエンドとして使用し、
PiBitというSNSアプリを開発する。
そのうえで、フロントエンド・API・DB・認証・テストまでの設計と実装を学び、
実務に近い構成での開発理解を深めることを目的とする。
コードはAIを使わずに書き進めていく。

### アプリ名・コンセプト

- アプリ名：PiBit（ピビット）
- 名前の由来：Piece × Orbit（Piece：一人ひとりの経験・考え方・価値観の欠片、Orbit：軌道・循環・繋がりの広がり）
- キャッチコピー：小さな欠片から、無限の繋がりへ。
- コンセプト：PiBitは、一人ひとりの経験・考え方・価値観を「Piece（欠片）」として共有し、新しい人や価値観との繋がりを生み出すSNSである。一人ひとりを形の異なるパズルのピースに見立て、それぞれの欠片が出会い、繋がることで新しい発見や可能性が生まれる。その繋がりは軌道のように広がり続け、完成することのない大きなパズルを形作る。人との出会いを通して自分の世界を広げていく場所とする。
- 以前のキャッチコピー・ブランドメッセージ（ブランドストーリーとして残す）：「欠片が、繋がりになる。」「終わりのない探求を、繋いでいく。」

### デザイン方針

- ロゴ：パズルのピースを人に見立て、2つのピースが繋がることで人と人の繋がりを表現する。周囲に軌道（Orbit）を配置し、繋がりの広がりや無限の可能性を表現する。
- デザイン方針：「UIは静かに、ユーザーの表現を主役に。」シック・ミニマル・ニュートラルなUIとし、白・黒・グレーを基本とした配色、シンプルな余白とタイポグラフィにする。Canvasの彩りはユーザーの投稿・写真・言葉・表現によって生まれるものとし、UI自体はカラフルに装飾しない。操作性やアクセシビリティに必要な状態表示は維持する。ロゴの配色・デザインは変更しない。
- UI技術：shadcn/ui + Tailwind CSS v4、アイコンはLucide Icons（MUI / Emotionは削除済み）。
- 過去の方針（参考）：青を基調に淡い紫をアクセント、親しみやすく少し未来的、UIはMUIを継続使用、としていた。現在はUI全体の方針としては採用していない。

### 機能名称

画面上の表示名称は以下を使用する（括弧内は一般名称）。

- Piece（投稿）
- Exploration（検索）
- Connect（フォロー）
- Resonance（いいね）
- Letter（リプライ）
- Spread（リポスト）
- Canvas（タイムライン）
- Inbox（通知）
- My Page（マイページ）

開発を通じて、以下を実現する。

- ユーザーがアカウントを作成し、ログインできる
- 投稿を作成・一覧表示できる
- 他ユーザーとの交流ができる
- ユーザーや投稿を検索し、通知を確認できる
- Next.jsとNestJSの責務分離と連携を学ぶ
- API設計とデータ設計の妥当性を検証する

## 2.対象

### 一般ユーザー

- アカウントを登録してログインする
- 自分の投稿を作成する
- 他人の投稿を閲覧する
- いいね・フォローなどの相互作用を行う

### 管理者

- 仕様上、MVPでは必須ではない
- ユーザー管理や投稿の確認・削除を担当する想定(センシティブ、不適切アカウント削除等)

## 3.ユーザーストーリー

### 認証

- ユーザーとして、新規登録をしてアカウントを作成したい
- ユーザーとして、登録済みのメールアドレスとパスワードでログインしたい
- ユーザーとして、ログアウトしたい
- ユーザーとして、パスワードを忘れた場合に再設定画面を利用したい（画面・ルートは将来仕様。実処理はMVP対象外）

### 投稿

- ユーザーとして、自分の考えや出来事を投稿したい
- ユーザーとして、タイムラインで最新の投稿を確認したい

### 交流

- ユーザーとして、投稿にいいねを付けたい
- ユーザーとして、投稿にリプライを送りたい
- ユーザーとして、投稿をリポストしたい
- ユーザーとして、他ユーザーをフォローしたい
- ユーザーとして、自分のプロフィールを確認したい
- ユーザーとして、自分のプロフィール情報を編集したい
- ユーザーとして、ユーザーや投稿を検索したい
- ユーザーとして、自分宛ての通知を確認したい

## 4.MVPの範囲

本プロジェクトのMVPは、認証、投稿・交流、プロフィール、ユーザー/投稿検索、通知を対象とする。具体的な採否・実装優先順位・完成条件は [mvp.md](./mvp.md) を基準とし、本節では別の機能一覧を管理しない。

管理者機能、画像添付・プロフィール画像変更、通知のリアルタイム配信、高度な検索、パスワード再設定・変更・アカウント削除の実処理などはMVP対象外または将来仕様として維持する。詳細は [mvp.md](./mvp.md) を参照する。

## 5.正常系

### 認証

- ユーザーが登録情報を入力してアカウントを作成できる
- 正しい認証情報でログインできる
- 認証済みユーザーがログアウトできる

### 投稿

- ログイン済みユーザーが投稿を作成できる
- 投稿一覧に新しい投稿が表示される
- 自分の投稿がタイムラインに表示される

### いいね / フォロー

- 認証済みユーザーが投稿にいいねをつけられる
- 同じ投稿に重複していいねできない
- ユーザーをフォローできる
- すでにフォロー済みのユーザーへの重複フォローが防止される
- 同じ投稿への重複リポストが防止される

### 検索・通知

- 公開ユーザーID・表示名の部分一致でユーザーを検索できる
- 投稿本文の部分一致で投稿を検索できる
- Resonance・Letter・Spread・Connectの通知を新しい順に確認できる
- 通知の既読状態と未読件数を管理できる（リアルタイム配信は対象外）

## 6.異常系

- 空の投稿内容を送信したときにエラーになる
- 既存ユーザーと同じメールアドレスで登録できない
- 誤ったパスワードでログインできない
- 未認証ユーザーが認証必須APIを呼び出せない
- 他ユーザーの投稿・リプライを削除できない
- 管理者API（将来実装）を管理者権限のないユーザーが呼び出せない
- 存在しないユーザーIDや投稿IDにアクセスしたときに404を返す
- 重複したいいね・フォロー・リポストを作成できない
- DBや外部APIの接続に失敗したときに適切なエラーハンドリングを行う

## 7.バリデーション方針

- 投稿内容は必須項目とし、空文字を許可しない
- 文字数制限を設ける
- メールアドレス形式を検証する
- パスワードの長さ・複雑さを検証する
- 入力値が不正な場合は、ユーザーにわかりやすいエラーメッセージを返す
- パスワードを平文で保存せず、適切な一方向性ハッシュとして保存する。具体的なアルゴリズム・設定は実装時に調査して決定する
- パスワードおよびパスワードハッシュなどの機密情報をAPIレスポンスに含めない
- 認証・認可・所有者確認はNestJS API側で検証する。管理者APIは将来実装時もサーバー側で管理者権限を検証する
- DB内部IDと公開ユーザーIDを区別し、公開ユーザーIDをDB内部IDの代わりに使用しない。IDをURLに隠すことだけを認可の根拠にしない

### HTTPエラー応答の基本方針

APIは状況に応じてHTTPステータスコードを使い分ける。下表は要件レベルの基本方針であり、認証方式や具体的なエラーレスポンス形式は未確定とする。

| ステータス | 使用する状況 |
|---|---|
| 400 Bad Request | 必須項目不足、形式不正、制約違反などリクエスト入力が不正 |
| 401 Unauthorized | 認証が必要だが、認証されていない |
| 403 Forbidden | 認証済みだが、対象操作の権限がない（所有者・管理者権限を含む） |
| 404 Not Found | 対象のユーザー・投稿などが存在しない |
| 409 Conflict | メールアドレスやいいね・フォロー・リポストなど、重複・状態競合がある |
| 500 Internal Server Error | 予期しないサーバー内部エラー。内部情報や機密情報は応答に含めない |

エラー応答の共通形式、文言、ログ方針はAPI設計時に検討する。

## 8.非機能要件

### 性能

- 投稿一覧が短時間で表示されること
- 一般的な投稿数で検索や取得が高速であること

### 保守性

- TypeScriptによる型安全性を維持する
- APIとDB設計を明確に分離する
- ディレクトリ責務を明示して構成する

### 可用性

- 主要なAPIは失敗時に適切なエラー応答を返す
- 不正な入力やDBエラーがアプリ全体を落とさない

## 9.完了条件

以下を満たした段階でMVP完了とする。

- [MVP定義](./mvp.md)の対象機能ごとの完成条件を満たす
- ユーザー登録・ログインができる
- Next.jsからNestJS側のAPIを呼び出して投稿の作成・表示ができる
- いいねとフォローが動作する
- 検索・通知を含むMVP必須機能が動作する
- 投稿・リプライの削除権限と重複防止がAPI側で守られる
- 基本的な異常系が適切に扱える(文字数制限等)
- パスワードが平文保存されず、APIレスポンスにパスワード等の機密情報が含まれない
- 認証・認可・所有者確認がNestJS API側で検証される
- APIとフロントエンドの責務が明確に分かれている
- テストが最低限実施できる

- MVPで実装する基本機能を超えるユーザー検索・投稿検索の高度化（具体的な条件・並び順は未決定）
- Letter（リプライ）・Spread（リポスト）の追加的な機能拡張（具体的な内容は未決定）
- 投稿への画像添付
- プロフィール画像・ヘッダー画像の変更
- 通知のリアルタイム配信
- パスワード再設定・パスワード変更・アカウント削除の実処理
- 管理者機能

MVPで実装する基本的なユーザー検索・投稿検索・Letter・Spread・Inboxを、未実装の将来機能として重複して列挙しない。検索の高度化やメディア機能等は、MVPの基本機能とは別の拡張として扱う。
